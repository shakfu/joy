# Compile Joy to C

The `compile-to-c` builtin compiles Joy quotations to standalone C programs that can be compiled with a standard C compiler and linked against the Joy runtime library.

## Quick Start

```joy
(* Compile a quotation to C source code *)
[5 dup * 3 +] compile-to-c.
(* Returns C source code as a string *)

(* Write compiled code directly to a file *)
[5 dup * 3 +] "/tmp/program.c" compile-to-file.
```

Compile and run the generated program:

```bash
gcc -O3 -DNOBDW \
    -I/path/to/joy/include \
    -I/path/to/joy/build/generated \
    -I/path/to/joy \
    /tmp/program.c \
    /path/to/joy/build/libjoycore_static.a \
    -lm -lsqlite3 \
    -o program

./program
# Output: 28
```

## Operators

| Operator | Stack Effect | Description |
|----------|--------------|-------------|
| `compile-to-c` | `[P] -> S` | Compile quotation P to C source string S |
| `compile-to-file` | `[P] "filename" ->` | Compile quotation P and write to file |

## Generated Code Structure

The compiler generates a complete C program with:

1. **Header includes** - Required Joy runtime headers
2. **Helper macros** - Stack manipulation, parameter validation
3. **Forward declarations** - For user-defined and generated functions
4. **User functions** - Compiled versions of DEFINE'd functions
5. **Main entry point** - `_joy_compiled_entry_()` containing the compiled quotation
6. **Runtime setup** - `main()` with environment initialization

Example output for `[5 dup *]`:

```c
/**
 * Joy program compiled to C
 * Generated by compile-to-c builtin
 */

#include "globals.h"
#include "builtin.h"

/* Stack manipulation macros */
#define SAVESTACK env->dump = LIST_NEWNODE(env->stck, env->dump)
/* ... */

/* Forward declarations */
void _joy_compiled_entry_(pEnv env);

/* Main program */
void _joy_compiled_entry_(pEnv env)
{
    /* constant-folded expression */
    NULLARY(INTEGER_NEWNODE, 25LL);  /* folded */
}

/* Entry point */
int main(int argc, char* argv[])
{
    /* ... runtime initialization ... */
    _joy_compiled_entry_(env);
    print_final_stack(env);
    return 0;
}
```

## Optimizations

The compiler applies several optimizations to generate efficient code.

### Constant Folding

Constant expressions are evaluated at compile time, eliminating runtime computation:

```joy
[2 3 +] compile-to-c.
(* Generates: NULLARY(INTEGER_NEWNODE, 5LL) *)
(* Instead of: push 2, push 3, call plus_ *)

[5 dup *] compile-to-c.
(* Generates: NULLARY(INTEGER_NEWNODE, 25LL) *)

[2 3 + 4 * 5 -] compile-to-c.
(* Generates: NULLARY(INTEGER_NEWNODE, 15LL) *)
(* Chains of operations are fully folded *)
```

Supported operations for constant folding:

| Category | Operations |
|----------|------------|
| Arithmetic | `+`, `-`, `*`, `/`, `rem`, `div`, `max`, `min` |
| Unary | `neg`, `abs`, `succ`, `pred`, `sign` |
| Comparison | `<`, `<=`, `>`, `>=`, `=`, `!=` |
| Logic | `and`, `or`, `xor`, `not` |
| Stack | `dup` (when followed by foldable ops) |

Float operations are also folded:

```joy
[3.14159 2.0 *] compile-to-c.
(* Generates: NULLARY(FLOAT_NEWNODE, 6.28318) *)
```

Division by zero is detected at compile time and prevents folding (falls back to runtime evaluation).

### Loop Inlining

The `while` and `times` combinators are compiled to native C loops:

```joy
[10 [1 -] times] compile-to-c.
```

Generates:

```c
/* inline times loop (10 iterations) */
{
    int64_t _times_i_1;
    for (_times_i_1 = 0; _times_i_1 < 10LL; _times_i_1++) {
        /* ... loop body ... */
    }
}
```

```joy
[[dup 0 >] [1 -] while] compile-to-c.
```

Generates:

```c
/* inline while loop */
{
    Index _while_stck_1 = env->stck;
    while (1) {
        env->stck = _while_stck_1;
        /* ... condition ... */
        {
            int _while_result_1 = nodevalue(env->stck).num;
            POP(env->stck);
            if (!_while_result_1) break;
        }
        env->stck = _while_stck_1;
        /* ... body ... */
        _while_stck_1 = env->stck;
    }
    env->stck = _while_stck_1;
}
```

### Operation Inlining

Common operations are inlined as optimized C code instead of function calls:

```joy
[1 2 +] compile-to-c.
```

Generates type-specialized code:

```c
/* + */
if (nodetype(env->stck) == INTEGER_ && nodetype(nextnode1(env->stck)) == INTEGER_) {
    BINARY(INTEGER_NEWNODE, nodevalue(nextnode1(env->stck)).num + nodevalue(env->stck).num);
} else { plus_(env); }
```

Inlined operations include: `dup`, `pop`, `swap`, `+`, `-`, `*`, `<`, `>`, `pred`, `succ`, `rollup`, `rolldown`.

## User-Defined Functions

Functions defined with `DEFINE` are compiled as separate C functions:

```joy
DEFINE square == dup *.
DEFINE cube == dup dup * *.
[[5 square] [5 cube] pfork] compile-to-c.
```

Generates:

```c
/* User-defined function declarations */
static void joy_word_square(pEnv env);
static void joy_word_cube(pEnv env);

/* User-defined: square */
static void joy_word_square(pEnv env)
{
    dup_(env);
    mul_(env);
}

/* User-defined: cube */
static void joy_word_cube(pEnv env)
{
    dup_(env);
    dup_(env);
    mul_(env);
    mul_(env);
}

void _joy_compiled_entry_(pEnv env)
{
    /* ... uses joy_word_square and joy_word_cube ... */
}
```

### Dependency Resolution

The compiler automatically collects all referenced user functions:

```joy
DEFINE helper == 2 *.
DEFINE process == helper 1 +.
DEFINE main == 5 process.
[[main] i] compile-to-c.
(* Both helper and process are included *)
```

### Recursive Functions

Recursive functions are supported via forward declarations:

```joy
DEFINE fact == [1 <=] [pop 1] [dup 1 - fact *] ifte.
[[5 fact] i] compile-to-c.
```

### Mutual Recursion

Mutually recursive functions work correctly:

```joy
DEFINE even? == [0 =] [true] [1 - odd?] ifte.
DEFINE odd? == [0 =] [false] [1 - even?] ifte.
[[10 even?] i] compile-to-c.
```

## Name Mangling

Joy names are converted to valid C identifiers:

| Joy Name | C Name |
|----------|--------|
| `square` | `joy_word_square` |
| `sum-of-squares` | `joy_word_sum_of_squares` |
| `list?` | `joy_word_list_p` |
| `++` | `joy_word__plus_plus` |
| `<>` | `joy_word__lt_gt` |

## Limitations

1. **Dynamic features** - Operations that require runtime symbol lookup may fall back to interpreter calls
2. **Side effects** - I/O operations execute at runtime, not compile time
3. **Recursive quotations** - Quotations that build themselves dynamically are not optimized
4. **Native types** - Native vectors/matrices (`v[...]`, `m[[...]]`) are not yet fully supported in compiled code

## Performance Comparison

Compiled Joy code typically runs 10-100x faster than interpreted code for computation-heavy programs:

| Program | Interpreted | Compiled | Speedup |
|---------|-------------|----------|---------|
| fib(30) | 850ms | 12ms | 70x |
| factorial(1000) | 45ms | 2ms | 22x |
| tight loop (1M) | 120ms | 1.5ms | 80x |

The performance gain depends on:
- How much constant folding can be applied
- Whether loops can be inlined
- The ratio of supported vs. unsupported operations

## Example: Fibonacci

```joy
DEFINE fib == [2 <] [] [1 - dup 1 - fib swap fib +] ifte.
[[30 fib] i] "/tmp/fib.c" compile-to-file.
```

Compile and run:

```bash
gcc -O3 -DNOBDW -I... /tmp/fib.c .../libjoycore_static.a -lm -o fib
time ./fib
# 832040
# real 0m0.012s
```

Compare with interpreted:

```bash
time echo '30 fib.' | ./joy
# 832040
# real 0m0.850s
```

## Troubleshooting

### Compilation Errors

If the generated C code fails to compile:

1. **Missing headers** - Ensure include paths are correct
2. **Missing library** - Link against `libjoycore_static.a`
3. **Undefined functions** - Some builtins may not be mapped; check compiler output

### Runtime Errors

If the compiled program crashes or produces wrong results:

1. **Stack underflow** - The quotation may expect values on the stack
2. **Type errors** - Ensure input types match expectations
3. **Unsupported operations** - Check if all operations are supported

### Debugging

Add debug output by modifying the generated code or using Joy's `debug-trace` before compiling to verify the program logic.
